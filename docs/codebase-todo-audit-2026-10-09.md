## 運用上の残件

1. 本番反映時に 021〜029 のマイグレーションを適用し、認可・データ補修結果を本番側で確認する。ローカル適用だけでは本番の脆弱性は解消しない。
2. 実データ量でタスク取得と履歴描画を再測定する。初期取得のオフセットによる欠落は 2026-10-11 に ID カーソルへ変更して解消。複数リクエストは単一時点の DB スナップショットではなく、取得済み範囲への新規追加や取得後の更新・削除は引き続き Realtime と再同期で回収する。
3. 必要ならオフライン更新キューを設計する。現在のオフライン対応は既に保存された画面とデータの閲覧、および代替画面の表示まで。
4. エラーを外部監視サービスに転送する場合は送信先と通知基準を決める。現在は実行環境のログで確認する。

## 継続対応（2026-10-11）

- 初期取得を 1000 件ずつの ID カーソル方式へ変更。編集で変わる表示順やオフセットを取得境界に使わず、ページ間の削除・並び替え・完了操作による未取得行の欠落を防ぐ。
- 全ページ取得後に従来の表示順（未完了優先、並び順、作成日時降順、ID）へ整列する。比較関数は Realtime と共通化し、「もっと見る」で取得済みの古い履歴は末尾に保持する。
- ページ間の変更、表示順、途中ページの取得失敗時に既存キャッシュを保持する動作を回帰テストで確認。追加の DB マイグレーションは不要。
- 今回の検証: `npm run test:run` は 40 ファイル・357 テスト合格。`npm run typecheck`、`npm run lint`、`npm run build`、`git diff --check` 合格。上記の pgTAP と Playwright は前回実施分。
