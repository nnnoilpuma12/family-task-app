# テスト整理・不足分の補強

対象: `nnnoilpuma12/family-task-app`、取得元コミット
`e45d2e7b0e930e61320662ee3c5b4940a2af0685`。

## 調査範囲と判断

`src/app`、`src/components`、`src/hooks`、`src/lib`、Supabase の
マイグレーション・DB テスト、Playwright、CI とテスト共通設定を照合した。
ファイル数やカバレッジ率だけを理由にテストを増減せず、既存ケースの検証内容と
アプリの境界（認証・世帯・通信失敗・並行更新）を基準にした。

| 領域 | 判断・対応 |
| --- | --- |
| タスク取得・更新 | ページング、並行更新、ロールバック、復元、履歴の既存テストを維持。ページサイズ・取得順の単独ケースを複数ページ取得ケースへ統合。並び替えの同じ RPC 引数を再確認するケースを削除し、既存ケースで呼び出し回数も確認 |
| 完了履歴 | API エラーと通信例外の両方で、読み込み解除・既存データ保持・再試行を追加。30 件の fixture に存在しない月が含まれていたため修正 |
| カテゴリ・定番品 | CRUD、失敗時の復元、カテゴリ削除時の移動、定番品の追加フォームの既存テストを維持 |
| リアルタイム・キャッシュ | 再接続、画面復帰、アカウント切替、イベント重複の既存テストを維持。更新待ちの列の参照カウント、列別解除、別タスク・別世帯の分離を追加 |
| 書き込みキュー | 一括操作が全対象を待つこと、先行応答が後続の待機を壊さないこと、同期例外からの回復を追加 |
| 並び順設定 | 重複していた変更・保存のケースを全選択肢の変更→保存→再マウント確認に統合。ストレージの読み書き例外を追加 |
| Push API | 未検証だった購読 POST/DELETE の認証、入力、保存ユーザー、削除スコープ、DB エラーを追加。送信 API の不正な JSON の型も検証 |
| Push 解除 | 通信例外、購読なし、非対応ブラウザ、ブラウザ側の解除失敗を追加。グローバル API とモック状態を後始末 |
| 認証 | コールバックのコード交換、パスワード再設定を含む内部遷移、外部遷移先の拒否、コードなし・交換失敗を追加 |
| DB | 別世帯のタスク・カテゴリ・定番品の不可視性、他世帯への書き込み拒否、RPC の世帯チェックと拒否後の自世帯データ保持を pgTAP 12 ケースで追加 |
| UI・画像・PWA | 既存の入力保持、ダイアログ、スワイプ、描画回数、画像検証、Service Worker、オフライン E2E は別の回帰を防いでいるため維持 |

## テストに対応する実装修正

- `push/subscribe` POST/DELETE と `push/send` POST は JSON の `null` を
  分割代入して例外になっていた。不正な型を 400 で返し、DB 操作に進めないようにした。
  購読鍵は空でない文字列、送信内容と世帯 ID は空でない文字列に限定する。
- `loadMoreCompleted` の通信例外を既存の API エラー処理へ流し、読み込み状態が
  戻らない状態と未処理の Promise rejection を防ぐ。
- Push 送信テストの環境変数は `vi.stubEnv` に変更し、テスト後に元へ戻す。
  fake timer も失敗の有無にかかわらず後始末する。

## 検証結果と制約

- Node の補助検証は **15 ケース成功**（ロジック 14 件と変更した TypeScript の
  構文確認 1 件）。実際のソースを読み込み、NextResponse・Supabase・web-push の
  外部境界はスタブに置き換えている。React や実 DB を通した結果ではない。
- 同じ補助検証を修正前ソースへ向けると、購読 POST/DELETE と送信 POST の
  `null` 処理を確認する 3 ケースが TypeError で失敗することを確認した。
- `npm run test:run`、`npm run lint`、`npm run typecheck` は実行を試みたが、
  それぞれ vitest / eslint / tsc が未導入で起動できなかった。
  `npm ci` は環境のプロキシへの接続失敗で完了していない。
- 新規・既存 Vitest、pgTAP、Playwright の成功は未確認。
  DB とブラウザの検証にはローカル Supabase が必要。
- 実行環境は Node 24.19.0。リポジトリ指定の 24.22.1 と異なる。

依存取得が可能な環境で、リポジトリ指定の Node を使って以下を実行する。

```sh
npm ci
npm run test:run
npm run lint
npm run typecheck
npx supabase start
npx supabase test db
npx playwright install chromium
npm run test:e2e
```

## 残るテスト候補

この変更は全経路の網羅を意味しない。次の対象は、実行基盤を利用できる環境で
追加・検証する価値がある。

- 認証フォーム、世帯作成フォーム、`usePushNotification` の失敗後の再試行。
- Providers の認証イベントと別タブイベントを含む、キャッシュ復元の統合テスト。
- 二つの DB セッションを使った同時参加・同時作成と、使用回数更新の競合。
- ログインからタスク作成・編集・完了・削除・復元までを通す E2E。
- 複数タイムゾーンでの日付表示と、実ブラウザでのフォーカス移動。

コミット・push・本番 DB 変更は行っていない。
